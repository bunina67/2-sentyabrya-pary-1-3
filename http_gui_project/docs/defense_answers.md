# Краткие ответы на вопросы защиты

## HTTP
1. **HTTP/1.0 и HTTP/1.1; Host.** В HTTP/1.1 соединение по умолчанию может быть постоянным, а `Host` обязателен для выбора виртуального хоста на одном IP.
2. **Content-Length.** Длина тела в байтах. Если его нет, границу ответа обычно определяют закрытием соединения или правилами другого Transfer-Encoding.
3. **Chunked.** Тело передаётся блоками: размер блока в hex, CRLF, данные, CRLF; нулевой блок завершает тело.
4. **GET и POST.** GET обычно получает представление ресурса; POST передаёт данные для обработки. Семантика определяется методом, а не только наличием тела.
5. **Keep-alive.** Повторное использование TCP-соединения для нескольких сообщений. Соединение закрывается по заголовку Connection, таймауту или правилам протокола.
6. **301/302/307.** 301 — постоянный перенос; 302 — временный; 307 — временный перенос с сохранением метода и тела. Клиент учитывает правила метода и безопасности.
7. **HEAD.** Сервер возвращает заголовки, которые соответствовали бы GET, но не тело; это отдельный метод протокола.
8. **Content-Type/charset.** Указывают тип представления и, для текстовых данных, кодировку.

## Сокеты
9. **listen/backlog.** `listen` переводит TCP-сокет в режим ожидания подключений; backlog задаёт очередь ожидающих соединений.
10. **accept/connect.** `connect` инициирует подключение клиента; `accept` принимает входящее подключение сервера.
11. **recv.** Может вернуть меньше данных, чем запрошено. Читать нужно циклом до ожидаемой длины, разделителя заголовков или закрытия соединения.
12. **SIGPIPE.** Сигнал при записи в закрытый канал/сокет в некоторых ОС. В Python обычно возникает исключение `BrokenPipeError`; его нужно обработать.
13. **close/shutdown.** `shutdown` отключает чтение/запись на соединении; `close` освобождает дескриптор.
14. **SO_REUSEADDR.** Позволяет быстрее повторно использовать локальный адрес после закрытия сервера.

## Python и ООП
15. **Контекстный менеджер Socket.** `__exit__` гарантирует закрытие сокета даже при исключении; без него возможна утечка ресурса.
16. **Callable в Router.** Хранится вызываемый объект, который можно вызвать напрямую; строковое имя потребовало бы небезопасного/хрупкого поиска функции.
17. **Исключения в __exit__.** Ресурс закрывается всегда; возвращение `False` не подавляет исключение.
18. **dataclass.** Автоматически создаёт типовые методы, например `__init__` и `__repr__`, и делает модель компактной.
19. **isinstance.** Проверяет тип во время выполнения. Часто можно использовать полиморфизм и ABC, чтобы не ветвиться по типам.
20. **Lock для логов.** Защищает общий изменяемый ресурс от одновременных изменений потоками. В проекте очередь отделяет серверные потоки от GUI.

## GUI и потоки
21. **Почему tkinter нельзя менять из рабочего потока?** Tkinter не является потокобезопасным; это вызывает зависания и нестабильность.
22. **root.after.** Планирует функцию в главном цикле GUI, поэтому интерфейс обновляется главным потоком.
23. **queue.Queue.** Потокобезопасная очередь для передачи результата или лог-события между потоками.
24. **Остановка accept.** Установить флаг остановки и закрыть listening-сокет либо использовать небольшой timeout, чтобы цикл мог проверить флаг.
25. **Закрытие окна во время запроса.** Фоновый поток не должен обращаться к уничтоженному виджету; результат безопасно игнорируют или отменяют запрос.

## Безопасность
26. **Заголовок 1 МБ.** Запрос нужно отклонить по лимиту заголовков; в проекте предел — 8 КБ.
27. **Request smuggling.** Разное толкование границ HTTP-сообщения разными прокси/серверами позволяет «протащить» скрытый запрос.
28. **Content-Length и Transfer-Encoding.** Несогласованные правила границ тела могут привести к request smuggling; безопасная политика — отклонять неоднозначные сообщения.
29. **Path traversal.** Попытка выйти за разрешённый каталог через `../`; пути нужно нормализовать и проверять, что итоговый путь остаётся внутри разрешённой директории.
30. **strcpy-аналоги.** Небезопасное копирование без проверки длины ведёт к переполнению буфера в языках с ручным управлением памятью; в Python всё равно нужны лимиты размера и валидация входных данных.
