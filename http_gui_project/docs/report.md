# Отчёт по заключительному проекту

## 1. Цель работы
Разработать десктопное приложение на Python, демонстрирующее устройство HTTP на уровне TCP-сокетов, объектно-ориентированную архитектуру и безопасное взаимодействие GUI с фоновыми потоками.

## 2. Реализованные компоненты
1. `Url` — разбор схемы, хоста, порта, пути и query-параметров; стандартные порты 80/443.
2. `Request` и `Response` — модели HTTP-сообщений на основе `dataclass`.
3. `Parser` — разбор стартовой строки и заголовков, ограничение размера заголовков, `Content-Length`, декодирование chunked-тела.
4. `Serializer` — формирование HTTP-сообщений, `Content-Length`, `Content-Type`, `Date` и `Connection`.
5. `Socket` — контекстный менеджер для закрытия сокета.
6. `TcpClient` и `HttpClient` — сетевой обмен, таймаут, GET/POST, TLS для HTTPS.
7. `Router` и `HttpServer` — маршрутизация и многопоточная обработка подключений.
8. GUI на `tkinter` — вкладки клиента и сервера; результаты фоновых задач передаются через `queue.Queue`, а GUI обновляется через `after`.

## 3. Реализованные маршруты
| Метод | Путь | Результат |
|---|---|---|
| GET | `/` | HTML-страница Hello |
| POST | `/echo` | Возвращает тело запроса и его Content-Type |
| GET | `/time` | Текущее время в JSON (UTC) |
| GET | `/headers` | Заголовки запроса в JSON |
| GET | `/status/{code}` | Ответ с указанным кодом в диапазоне 100–599 |
| любой | неизвестный путь | 404 Not Found |
| некорректный HTTP | — | 400 Bad Request |

## 4. Многопоточность и управление ресурсами
Основной поток tkinter не выполняет сетевые операции. Клиентский запрос выполняется в фоновом потоке; результат поступает через очередь и отображается методом `after`. Сервер принимает подключения в рабочем потоке и создаёт поток для каждого соединения. Для остановки устанавливается событие, закрывается listening-сокет и ожидается завершение основного серверного потока. Сокеты закрываются контекстными менеджерами.

## 5. Тестирование
Автоматические тесты расположены в `tests/`: проверяются URL, ошибки парсинга, заголовки, Content-Length, chunked, сериализация и интеграция клиента с сервером. Для ручной проверки используйте команды `curl` из README. Фактические результаты запуска следует зафиксировать после выполнения тестов на компьютере, где будет демонстрироваться проект.

## 6. Безопасность и ограничения
Парсер ограничивает заголовки 8 КБ, размер тела запроса 10 МБ, клиентский ответ 20 МБ. Не допускается некорректный Content-Length и некорректные заголовки. Сервер по умолчанию доступен только через loopback `127.0.0.1`. Конфликтующие `Content-Length` и `Transfer-Encoding` требуют дополнительного строгого отказа в промышленной реализации; проект предназначен для учебной демонстрации, а не публичного размещения.

## 8. Вывод
В проекте реализованы основные компоненты HTTP-клиента и сервера без готовых HTTP-библиотек, GUI на tkinter, обработка сетевых операций в фоновых потоках, журналирование и автоматические тесты. Для сдачи необходимо приложить реальные скриншоты GUI, выполнения тестов и ручных запросов.
